## 四、已定的决定

- **最终形态是独立的 Paseo 插件，没有中心网页**（2026-11-25，用户）。网页在 B17 下线。
- **`/mcp` 保留**：中心所在机器和 gx10 上的 Claude Code、Codex 都配置了它，它是给 agent 用的，不是给人看的页面。B17 只下线网页，`/mcp` 继续由插件提供。这是协调者的建议，用户反对的话在 B17 之前改。
- **插件对工作 agent 只读**：插件不向工作 agent 发消息。总管 agent 由用户点"问总管"时创建；它要指挥其他 agent 时，用 Paseo 自带的工具，这是它自己的动作，不经过插件。
- **总管 agent 跑在中心所在的机器上**，默认不能执行命令、不能改文件。
- **界面按问题来排**（设计文档第八节）：

  | 用户的问题 | 对应的地方 |
  |---|---|
  | 现在要我做什么 | 主屏"待处理"页签 |
  | 现在谁在干什么 | 主屏"实时"页签 |
  | 各项目到哪了 | 主屏"看板"页签 |
  | 这个项目怎么回事 | 项目页 |
  | 这个 session 在干什么 | session 页 |
  | 这个结论哪来的 | 回合页 |
  | 系统自己还好吗 | 主屏"来源"页签 |
  | 我想问一句、或让它去办 | 问总管 |

### B5a 看板（只读）

**注册**

| 注册 | 内容 |
|---|---|
| `addSidebarHeaderItem` | "任务看板"一行，带待处理数量，点开主屏 |
| `addScreen` `board` | 主屏，四个页签：待处理、实时、看板、来源 |
| `addScreen` `project` | 项目页，参数为项目 ID |
| `addScreen` `session` | session 页，参数为 session 地址 |
| `addScreen` `turn` | 回合页，参数为回合地址 |
| `addWorkspacePanel` | 当前工作区所属项目的简报、未完成 todo 和阻塞，带"打开项目页" |
| `addCommandCenterItem` | "打开任务看板" |

**各屏内容**

- **待处理**：`readOverview` 的待处理列表，顺序同 B9。每条显示等了多久；关联了 session 的，带"在 Paseo 里打开"。
- **实时**：按机器分组的运行中 session，每个显示所属项目、当前回合、已运行多久、发起这一轮的消息开头。
- **看板**：`listProjects` 的项目卡片，按阶段分列；紧凑布局下改为单列加阶段筛选。上面有一个搜索框，调用 `searchContext`，结果按地址打开对应的页。
- **来源**：`readOverview` 的盲区：各机器的状态、待摘要、拒摘、工具详情用量。
- **项目页**：`getProject` 的简报、等你的事、里程碑和 todo、决策、阻塞、关联的 session、时间线。证据和核对依据都是可点的地址。
- **session 页**：`readSession` 的卡片（注明截至第几轮）和回合大纲，带"在 Paseo 里打开"。
- **回合页**：`readTurn` 的条目。点工具调用时用 `readItem` 分页读原文，走显式读取路径，可以回源。
- **工作区面板**：用工作区的目录找到关联的 session，再找到所属项目。找不到时显示"这个工作区还没有关联的项目"。

**规则**

- **数据**：全部通过插件 RPC 调用上面这些现有函数，返回结构化数据，渲染在客户端做。不复制查询逻辑。
- **实时更新**：用 `defineSubscription` 把中心现有的变更通知（`ChangeFeed`）推给打开着的界面，界面收到后让对应的查询失效重取。不靠轮询。
- **在 Paseo 里打开**：用 `navigation.openAgent({ agentId, serverId })`。agentId 和 serverId 从这个 session 的 Paseo 来源观察里取，远端机器的 agent 也能打开。
- **每条模型产出的结论都标两样**：截至时间（或截至第几轮），以及来源类型（记录、推断、确认，现有字段已经区分）。相关来源有盲区时，页面顶部显示提示条。
- **自上次以来**：主屏的读者游标用一个固定的读者 ID（例如 `panel`），和 MCP 的各把 key 分开。
- **中心未启动时**（库缺失等）：各屏显示原因，并提供跳到设置页的入口。

**测试**

| 用例 | 预期 |
|---|---|
| 各 RPC 的返回 | 和直接调用对应领域函数的结果一致 |
| 中心有一条变更 | 订阅推送一次通知 |
| 一个远端机器上的 session | "在 Paseo 里打开"带上那台机器的 serverId |
| 工作区目录没有关联 session | 面板显示"还没有关联的项目" |
| 中心未启动 | RPC 返回原因，不抛未处理的错误 |

界面部分在隔离 daemon 上实际打开每个屏幕，桌面和紧凑布局各截一张图，写进汇报。

### B5b 看板（写操作）

**目的**：补齐网页现有的全部操作，之后网页才能下线。

**操作**

| 操作 | 现有入口 | 插件里放在 |
|---|---|---|
| 回答、忽略问题 | `answerQuestion`、`dismissQuestion` | 待处理、项目页 |
| 稍后提醒、不再提醒 | `snoozeReminder` | 待处理 |
| 新建项目，改标题、一句话、为什么、完成标准、优先级，解锁字段 | `execute` 的对应操作 | 看板、项目页 |
| 改阶段 | `transition_stage` | 项目页 |
| 里程碑、todo、阻塞的增删改，决策的记录和删除 | `execute` 的对应操作 | 项目页 |
| 关联或取消关联 session、忽略 session | `link_session`、`unlink_session`、`ignore_session` | session 页、项目页 |
| 撤销一条变更 | 撤销事件 | 项目页时间线 |
| 合并项目：预览、应用 | merge-previews | 项目页 |
| 手动同步 | `/sync` 的逻辑 | 主屏 |

**规则**

- 领域操作只用一个 RPC：输入 `{ op, args }`，按现有的 `OP_SCHEMAS` 校验，以用户身份执行，返回 `OpResult`。被拒绝时界面显示原因。
- 回答、忽略、撤销、提醒、合并、同步，各自调用现有函数，不另写逻辑。
- 不需要网页那套管理员登录：插件 RPC 只有连着这台 daemon 的 app 能调用，信任边界就是 Paseo 的连接。
- 每个写操作成功后，由订阅通知刷新界面，不在客户端手动改缓存。

**测试**

| 用例 | 预期 |
|---|---|
| 同一个操作分别经 RPC 和网页路由执行 | 产生相同的事件和结果 |
| 参数不合法 | 返回校验错误，数据库不变 |
| 被领域规则拒绝（例如改了被锁的字段） | 返回原因，数据库不变 |
| 撤销一条变更 | 和网页撤销的效果相同 |

### B6 问总管

**目的**：从看板打开一个能读全部 context 的 agent，回答问题、在需要时指挥其他 agent。设计见设计文档第七节。

**设置**：设置页的"模型"一节加"总管"一项：provider 和模型，使用 Claude，默认模型 `claude-opus-5-5`。Paseo 0.17.3 的 Codex 只读沙箱可以执行命令，逐 agent 配置不接受关闭 shell 的开关，设置页说明原因。存储同 B14，走现有的 `settings.ts`。

**入口**

- 主屏右上角、项目页右上角各一个"问总管"按钮，⌘K 里也有一项。
- 点击后可以输入一句话（可留空）。从项目页进入时，自动带上项目 ID。

**创建**（插件 RPC，在中心所在机器的 daemon 上，用插件已有的本机 Paseo 客户端）

- 工作目录：插件状态目录下的 `steward/`，不存在就新建，权限 700。
- 标题"总管"，标签 `task-manager/role: steward`。
- provider 和模型取自设置。
- 不能执行命令、不能改文件：Claude 使用逐 agent 的主会话工具白名单和 `config.options.disallowedTools`。只保留 Read、Grep、Glob，下列十个看板工具（含外部 agent-pm 的同名工具），以及 Paseo 的 list_hosts、list_workspaces、list_agents、get_agent_status、get_agent_activity、send_agent_prompt、create_agent。
- 总管固定使用 Claude 的 default 模式。只读文件、看板工具（含 pm_report）和 Paseo 的目录、状态与活动查询预先批准；send_agent_prompt、create_agent 每次须由用户批准。
- create_agent 在申请批准前拒绝含 settings.modeId 或非空 settings.features 的请求；同 provider 的子 agent 继承总管的 default 模式；跨 provider 时不指定模式，由 Paseo 决定是否接受。
- 每次 send_agent_prompt 都在申请批准前检查参数。只允许默认排队或显式 queue；带 sessionMode、interrupt 或 steer 时，向模型返回拒绝原因。
- 初始消息：用户输入的那句话；留空时为"看一下现在的全局态势，告诉我最需要注意的事"。从项目页进入时，末尾附上项目 ID。
- 返回 agentId 和 serverId，界面随即用 `navigation.openAgent` 打开它。

**打开时注入**（`server.addHook("agent.open.before")`，只对带 `task-manager/role: steward` 标签的 agent）

- 首次打开时注入角色说明和注明生成时间的全局态势快照（`pm_overview` 的文字，读者 ID 用 `steward`）。重开后沿用原会话，由角色说明要求模型在回答每个新问题前刷新态势。
- 挂上读取工具：`pm_overview`、`pm_get_brief`、`pm_get_project`、`pm_timeline`、`pm_search`、`pm_list_sessions`、`pm_get_session`、`pm_get_turn`、`pm_read_raw`、`pm_report`。用 `defineAgentTool` 包装现有的工具定义，不另写一份。读取走显式路径，可以回源。

**角色说明**（原样使用，可以调整措辞，不要扩写）：

> 你是用户所有项目的总管，负责回答进展问题，并在用户要求时协调其他 agent。开始时附上的"全局态势"是当时的快照。快照可能已过时，回答用户的每个新问题前，先调用 pm_overview 获取最新态势，再按地址下钻核实，结论后面写上依据的地址。需要让其他 agent 做事时，用 Paseo 的工具（列出 agent、给 agent 发消息、创建 agent），发之前先告诉用户你打算发什么。你不能执行命令，也不能改文件。需要记入看板的结论用 pm_report 上报。

**需要在隔离 daemon 上验证**（任何一项不成立都停下来汇报）

- 插件创建的 agent 第一次打开时，按标签挂上了工具和系统提示。
- 禁用执行命令和写文件的工具后，Paseo 自带的工具和插件挂的工具仍然可用。Paseo 自带工具需要在 host 设置里打开"Enable Paseo tools"，隔离 daemon 上要先打开。
- Claude 和 Codex 两种 provider 各验一次。
- 没带标签的 agent 拿不到这些工具和提示。
- 显式重开和 daemon 重启恢复后，模型的工具清单、发消息参数限制和看板读取能力仍然生效。

**测试**

| 用例 | 预期 |
|---|---|
| 带总管标签的 Claude agent 首次打开 | 拿到读取工具、角色说明和带生成时间的全局态势快照 |
| 显式重开或 daemon 重启后恢复 | 工具清单相同，消息参数检查有效，读取可用；回答前主动刷新态势 |
| 普通 agent 打开 | 什么都不加 |
| 创建总管（假 Paseo 客户端） | 工作目录、标签、模型、禁用项、初始消息都正确 |
| 从项目页创建 | 初始消息里有项目 ID |
| 总管调用 `pm_get_turn` | 结果和 MCP 同名工具相同 |

### B18 正常停止时交回采集租约

**顺序**：B5b 之后、B6 之前做。

插件清理、取消选中来源或独立采集器正常退出时，停止安排采集并等待在途写入结束。未收到确认的批次保留在离线暂存中。通过进程内客户端或 HTTP 的 `POST /ingest/v2/lease/release` 调用同一个入库函数，按来源、实例和租约 epoch 匹配，将到期时间设为中心当前时间。

### B19 看板显示打磨

**目的**：B5a、B5b 上线后，界面上还有几处直接显示内部数据，用户读不懂。

**改动**（只改显示，不改数据和接口语义）

- **问题选项**：现在显示原始操作和参数，例如 `改阶段 project=p_1 stage=verify`。改成一句话，例如"把「项目名」的阶段改为 验证"。项目、里程碑、todo 等引用显示标题，不显示 ID。复用 `src/shared/operation-labels.ts`，需要的话在那里补充，网页和插件共用。
- **时间线**：
  - `blockers:b_1` 这类实体引用，改为显示条目的文字或标题（条目已删除时显示"已删除的阻塞"之类）；
  - 操作者 `user` 显示为"你"，`ai:curator` 显示为"整理员"，其他 AI 角色同理；
  - "记录 #7"这类事件编号不显示，撤销等操作仍按编号执行。
- **时间**：看板上所有时间改为设备本地时区的短格式。今天的只显示时分，其他显示月日时分，跨年的带年份。需要精确时间的地方，按下或悬停时显示完整时间。"截至 …"同样处理。
- **偶发失败的测试**：`plugin/tests/lifecycle.test.ts` 先找空闲端口、再让中心绑定，两步之间有竞争，整套并发运行时偶尔失败。改为让中心绑定端口 0，从 `startCenter` 返回的 `port` 读实际端口。所有用到"先找空闲端口"写法的测试一并检查。

**测试**

| 用例 | 预期 |
|---|---|
| 一个"改阶段"选项 | 显示项目标题和阶段的中文名，不出现 `project=`、`stage=` |
| 时间线里的阻塞条目 | 显示阻塞的文字；条目已删除时显示占位文字 |
| 操作者为 `user`、`ai:curator` | 分别显示"你"、"整理员" |
| 今天、今年早些时候、去年的时间 | 分别显示时分、月日时分、带年份 |
| 插件测试整套连续运行 10 次 | 全部通过 |
